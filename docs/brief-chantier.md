# Brief chantier (gabarit à coller à chaque agent)

Chantier : <sujet> · Branche : `claude/<sujet>` · Demande : <1-3 lignes>

1. **Périmètre** : fichiers autorisés : <liste>. Tout autre fichier (surtout `public/app.js`, `index.html`, `styles.css`, `sw.js`, `i18n.js`, `server/db.js`, `server/index.js`) = s'arrêter et signaler. Ne rien élargir.
2. **Charte** : lire `CLAUDE.md`, `SIMPLIFICATION.md`, `DESIGN.md`. Violet #674EA7, sombre seulement, pop-up centrés avec ✕, pas de fenêtre du bas. Règles produit verrouillées intouchables.
3. **Démarrage** : `scripts/new-worktree.sh <sujet>` puis `set -a; . ./.chantier.env; set +a` (PORT et NOESIS_DATA_DIR propres). Sinon : worktree depuis `git fetch origin staging` + FETCH_HEAD.
4. **Tests** : `node --check` sur chaque `.js` touché ; `node test/run-tests.js` (inclut le garde d'intégrité), **suite complète : toujours via `scripts/suite-verrouillee.sh`** (voir 4 bis) ; serveur : `PORT`/`NOESIS_DATA_DIR` du `.chantier.env`, jamais ceux d'un autre chantier ; UI : une capture de l'écran touché.
5. **Livraison** : `git fetch origin && git rebase origin/staging` (terminé) → si `public/` change : `node scripts/bump-sw.js` → `git diff origin/staging` limité à la demande (aucun fichier vide/tronqué) → commit en français → `git push origin HEAD:staging`.
6. **Interdits** : `git stash` (utiliser un commit WIP) ; `--force` ; travailler dans le dépôt principal ; fusion vers `main` ; paiement/Stripe, légal/Loi 25, suppression de données (préparer, ne pas exécuter) ; ajouter une dépendance sans le dire.
7. **Compte rendu** : 2-3 lignes : fait / à valider visuellement / bloqué. Pas de fichier de rapport.
8. **Dossiers temporaires** : tests et scripts créent leurs dossiers via `test/lib/tmpdir` (`mkTmp`, nettoyage auto à la sortie, erreur et signaux). Supprimer ses propres dossiers temporaires (`mktemp -d`, `NOESIS_DATA_DIR`) par chemin exact en fin de travail, jamais de balayage de `/tmp` (pas de `rm -rf /tmp/*`, pas de `find /tmp -delete`). `node test/run-tests.js` échoue s'il reste un dossier temporaire (la suite redirige `TMPDIR` vers une racine privée : tout préfixe, `tmt-` comme `noesis-`, est couvert ; ne jamais coder `/tmp` en dur, passer par `os.tmpdir()` ou `mkTmp`). Rediriger une sortie de test uniquement vers un fichier créé par `mktemp` ou `"${TMPDIR:?}/..."` (jamais `$TMPDIR/x` avec `TMPDIR` vide : cela écrit à la racine `/x`).
9. **Titres de tâches personnelles** : jamais de titre de tâche personnelle recopié mot pour mot dans le dépôt : id + résumé neutre (≤ 6 mots, sans nom de personne ni client).
10. **4 bis. Suite complète sérialisée** : la machine a 2 CPU ; lancer la suite à plusieurs la rend lente et instable. `scripts/suite-verrouillee.sh` (même arguments que `run-tests.js`) prend le verrou `/tmp/tmt-suite.lock` (hors dépôt) : si une autre suite tourne, il l'indique et attend (25 min max, sinon code 75 : ne pas pousser sans suite verte). La suite elle-même est limitée à 25 min. Le verrou est libéré à la sortie, même si le script est tué. Jamais de `node test/run-tests.js` direct pour la suite complète.
11. **Règle de rebase tardif (assumée)** : on ne boucle pas sur un `staging` très actif. Après le dernier rebase, si le diff entrant (`git diff HEAD@{1} HEAD` ou `ORIG_HEAD..HEAD`) ne touche que `docs/` ou un bump de `public/sw.js`, relancer au minimum `sw-bump-test` + les tests de ton périmètre ; sinon, suite complète via le script. Une suite verte sur la tête exacte n'est donc exigée que si du code est entré.
12. **Hook optionnel anti-oubli de bump sw** : `scripts/pre-push-sw.sh` refuse un push dont les commits touchent `public/` sans changer `CACHE_VERSION` de `public/sw.js`. Non imposé ; installation : `ln -sf ../../scripts/pre-push-sw.sh "$(git rev-parse --git-path hooks)/pre-push"` (contournement : `--no-verify`).
13. **Première minute après un déploiement** : `scripts/smoke-staging.sh [URL]` (curl, GET seulement, aucun secret ; défaut `http://localhost:$PORT`, jamais la prod).
    - Quand : dès que Railway affiche le déploiement de `staging` terminé (https://web-staging-6d1b.up.railway.app).
    - Il vérifie : `/healthz` 200, accueil 200, `app.js` et `styles.css` avec `?v=` en cache immutable, gzip/br actif, `sw.js` sans cache.
    - Sortie : une ligne ok/ECHEC par contrôle, code 0 si tout passe ; un ECHEC = ne rien annoncer, ouvrir un correctif.
    - Garde-fous de dépôt : `test/garde-sources-test.js` (suite) refuse marqueur de conflit hors `docs/`, `node --check` en échec sur `public/**/*.js`, CSS déséquilibré ; le hook `pre-push-sw.sh` refuse aussi un diff qui ajoute un marqueur.
14. **Règles de rangement (obligatoires)** : lire `docs/regles-rangement.md` avant toute modification de `public/`, et joindre au compte rendu la checklist R1–R22 et F1–F5 (chaque règle cochée ou justifiée) avec les captures avant/après à 390 px et 360 px. Sans cela, le relecteur refuse la branche.
